## Decisive correction

On this Apple-silicon host, a completely unsigned native arm64 executable is
not a runnable test form. AMFI rejects it at exec time before main. It therefore
cannot extract an audit token, inventory Keychain attributes, run a Keychain
lifecycle, emit an OSStatus, or clean up an item.

This amendment retires completely unsigned execution from M3.03. The only
executable no-Developer row is an explicitly ad-hoc-signed arm64 binary created
with:

    /usr/bin/codesign --force -s - --timestamp=none <binary>

The signature has no signing identity, Team ID, provisioning profile,
entitlement payload, keychain-access-groups entitlement, or
kSecAttrAccessGroup request. The extra --force is required because the current
Apple-silicon linker produces an ad-hoc signature by default; it does not
change the requested signing identity of dash.

Ad-hoc signing is only the minimum executable integrity form on this host. It
does not provide Developer ID identity, trusted caller identity, notarization,
Gatekeeper distribution acceptance, a stable identity across rebuilds,
hardware custody, non-exportability, or a public-distribution claim. Another
process running as the same user remains in the admitted threat boundary. No
later artifact may describe this lane as signed for distribution or
Apple-trusted.

The strings unsigned and adhoc remain valid only as historical residue
namespace labels:

- skillmap-m303-dp-unsigned-[24 lowercase hex]
- skillmap-m303-dp-adhoc-[24 lowercase hex]

One explicitly ad-hoc-signed recovery binary scans both namespaces. It never
executes a completely unsigned binary.

directory. The complete-bundle evidence set consists of that core bundle, the
fixed rendezvous, and path 5. The complete-bundle boundary is crossed only
after every member below has passed its final metadata/hash/fsync check and
path 5 has passed successful exclusive creation, complete canonical write,
read-back verification, and fsync. After that boundary, no member may be
rewritten, copied over, rebuilt, re-signed, or replaced. The evidence set
contains:

1. recovery-adhoc — the final regular non-symlink executable, current UID,
   mode 0755, link count one, and exact receipt-bound SHA-256;
2. run-record.json — regular non-symlink, current UID, mode 0600, link count

   absolute path;
3. exactly one protected manifest:

#### Fixed protected run-record rendezvous

The rendezvous filename is public, fixed, and non-secret:

    /tmp/skillmap-m303-dp-keychain-adhoc-gate-v1.locator

On this target, /tmp must resolve to exactly /private/tmp, whose no-follow
opened target is a root-owned directory with mode 01777. The runner generates
one cryptographically random 128-bit lowercase-hex run ID internally and
constructs the run-record path in process memory as:

    /private/tmp/skillmap-m303-recovery-<32-lowercase-hex>/run-record.json

The only persisted or transported representation of that raw absolute
run-record path is the rendezvous file's exact content:

    UTF8(absolute_run_record_path) || 0x0A

Before creating the run directory or compiling, the initial runner opens the
fixed rendezvous filename exactly once with
O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW and creation mode 0600. EEXIST, ELOOP, any
pre-existing directory entry, or inability to use those flags is
PRE_BUNDLE_BLOCKED; the runner does not read, replace, chmod, truncate, unlink,
or remove the colliding entry and does not try another name. After creation it
