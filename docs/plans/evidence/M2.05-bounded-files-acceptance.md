## Contract implemented

The single transactional migration creates only `private.managed_skill_files`, its two private trigger functions, and its supporting index. Each row stores an immutable file identity and opaque future blob-reference coordinate for one accepted immutable Managed Skill Version:

- internal UUID plus checked globally unique `msf_` public ID;
- repeated account, Managed Skill, and version UUIDs bound by full composite foreign keys;
- canonical relative path, bounded media type, declared byte size, exact lowercase SHA-256 file digest, opaque storage key, executable declaration, nonnegative ordinal, and server-owned creation time;
- exact uniqueness for `(account_id, version_id, relative_path)`, `(account_id, version_id, ordinal)`, and global `storage_key`.

The path constraint rejects empty, absolute, drive/scheme-prefixed, backslash, empty-segment, trailing-slash, literal `.`/`..` segment, control-character, non-NFC, greater-than-512-UTF-8-byte, and greater-than-32-segment inputs. It stores no normalized alias. Upstream M1.03/M1.04 remains authoritative for case-fold collision keys, MIME allow/deny classification, scripts, links, special files, frontmatter, actual bytes, and digest verification; SQL does not invent a second parser or URL-decoding rule.

Declared `byte_size` is constrained to `0..16,777,216`; a canonical `SKILL.md` row is additionally constrained to `0..1,048,576`. The deferred constraint trigger locks the immutable parent version first, then all matching file rows in UUID order, and enforces at most 2,048 files and at most 67,108,864 aggregate declared bytes. A missing parent during cascade deletion is treated as no remaining aggregate, so account/skill/version cascade cleanup is not blocked. The trigger performs no external operation.

All row coordinates, including the opaque storage key, are immutable after insertion. Deletion remains legal for later child-to-parent cleanup. The implementation uses a conservative 128-byte relational media-type bound and 512-byte opaque storage-key bound. These are storage limits, not MIME or M2.06 key grammars; M2.06 still owns the exact private bucket/key convention and object binding.

The table enables and forces RLS with zero policies. The table and both trigger functions are explicitly revoked from `public`, `anon`, `authenticated`, `service_role`, and `skillmap_vault_definer`. No API projection, security-definer function, grant, storage object, storage policy, or upload behavior is created.
