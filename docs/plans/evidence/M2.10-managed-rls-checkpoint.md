## Corrected design (vs. the untrusted partial candidate)

The candidate `20260727060900` (from the interrupted Orca task) was treated as an untrusted
partial candidate, not accepted work. On clean review it carried the following defects, all
repaired:

1. **Duplicate projection** — it created a new `api.my_managed_skills_projection` duplicating
   the accepted M2.03 `api.my_managed_skills` view, and invented `my_owned_versions_projection`.
   The final migration **reuses `api.my_managed_skills`** (name + columns), and adds the three
   NEW `api.my_managed_skill_versions / _releases / _files` views required by M2.02 §4.8.
2. **auth.uid() un-reachable by the NOLOGIN definer** — the frozen contract sets SECURITY
   DEFINER owner functions to derive identity via `auth.uid()`, but the NOLOGIN definer holds no
   USAGE on the provider-owned `auth` schema, and postgres (migration runner) holds plain USAGE
   with no GRANT OPTION (auth is owned by `supabase_admin`; postgres is not superuser here), so
   `GRANT USAGE ON SCHEMA auth` is a silent no-op (verified live). Fixed with two SECURITY
   DEFINER helper functions owned by `postgres` (which holds `auth` USAGE), EXECUTE-granted only
   to the vault definer: `private.current_request_uid()`/`_role()`. Every M2.10 owner-definer
   path and the private activation body call `private.current_request_uid()` instead of `auth.uid()`
   directly. This preserves the frozen `auth.uid()`/`auth.role()` contract, changes no provider
   schema, and uses no `current_setting`.
3. **security_invoker projections cannot serve base SELECT-less callers** — a security_invoker
   view's body runs with the invoker's privilege; granting base SELECT would violate the frozen
   M2.04 “no base table access” guard (verified: `select * from private.managed_skill_versions`
    throws 42501 for authenticated, which the frozen suite requires). Fixed per coordinator: each
   api view stays `security_invoker=true`/`security_barrier=true` but SELECTs from a bounded
   private SECURITY DEFINER STABLE helper owned by the NOLOGIN definer; authenticated is granted
   SELECT on the view + EXECUTE on that exact helper, with NO base-table privilege and no
   `auth`-provider grant of any kind. Direct base access remains denied (42501). Because
   authenticated carries the M1 private-schema USAGE + helper EXECUTE, the private helper
   function names themselves are reachable — a direct `private.my_owner_*()` call is
   owner-scoped and equivalent to its api projection (asserted in the focused suite).
4. **Missing `managed_skill_files_definer_all` policy** — the files projection helper runs as
   the definer under FORCE RLS; added the per-owner definer-all policy for files.
5. **Definer couldn't INSERT/UPDATE** for `create_managed_skill`(`update_managed_skill_metadata`) —
   added scoped `INSERT` and `UPDATE(display_name, description)` grants for the definer only,
   inside the per-owner definer-all policy bounds.
6. **Independent audit coverage repair** — the initial focused suite catalog-checked the new
   owner functions but did not execute the required owner-A/account-B/anon mutation matrix.
   The accepted suite now executes owner create/update, foreign update denial, anon execution
   denial, eligible activation, foreign activation denial with exact non-enumerating result,
   pointer/revision preservation, bounded direct-helper ownership, and identity-helper denial
   through reachable roles. The coordinator also restored `finish()` and aligned the declared
   plan with the emitted 132 assertions; an intermediate false-green 128/129 plan mismatch is
   not acceptance evidence.

Deliberate keeper: authenticated retains the M1 baseline `USAGE` on `private` (it is required by
the pre-existing catalog/postgrest surface and cannot be revoked), and it holds EXECUTE on the
bounded projection helpers so the security_invoker views resolve. Both grant no per-table
privilege: no managed base-table INSERT/UPDATE/DELETE/SELECT grant is made to any browser role,
and the identity helpers (`current_request_uid`/`_role`) are granted to nobody but the definer.
