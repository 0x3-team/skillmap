## Corrective findings addressed (Codex round 1)

1. **Account-scoped idempotency.** Replaced `unique(account_id, device_id, request_id)`
   with `unique(account_id, request_id)`. Lookup in `record_route_decision` is by
   `account_id + request_id` only (P4), after validating the supplied current device
   (P3-style). The same account + request id on another device with a differing
   fingerprint is a non-disclosing `idempotency conflict`; it cannot create a second
   decision.
2. **Required release lineage.** Added mandatory `release_id` to
   `route_decision_selections` and to the `p_selections` JSON. The composite FK
   `(account_id, managed_skill_id, version_id, release_id)` references
   `managed_skill_releases`, backed by a new
   `managed_skill_releases_nav_key (account_id, managed_skill_id, version_id, id)`
   unique key added in this forward migration. Per-decision uniqueness of the selected
   binding is enforced via `route_decision_selections_binding_key`.
3. **Correction vocabulary.** Replaced the invented `reroute/override/clarify/withdraw`
   + `applied/rejected/...` vocabulary with the product's bounded feedback outcome
   `correct / wrong / unnecessary / missed` (glossary line 143; M5.14/M6.13/M9.09).
   The implementation is renamed to `private.record_route_correction`. Exactly one
   immutable slot per decision and idempotent replay are preserved. `wrong`/`missed`
   may carry an optional owned alternative lineage (pure UUID `alt_managed_skill_id` /
   `alt_version_id` / `alt_release_id` with a composite FK), all-null or all-non-null,
   and foreign/mismatched/expired alternatives are rejected. No second processing-
   status vocabulary is invented.
4. **Expiry dominates replay.** `record_route_decision` now refuses an exact replay
   once `decision_expiry_at` has passed (and once `replay_guaranteed_until` has passed
   inside the window), failing closed with a non-disclosing error; it never returns an
   expired stored row. The production function carries NO test-only replay/expiry
   parameters: replay (24 h) and decision authority (30 d) are always the M1.09/M1.11
   defaults. Replay also requires the exact same current device (compare on
   `existing.device_id`), so a second device can never replay or create a second
   decision for the same account request id. The pgTAP test models an aged/restored
   row by backdating `created_at` (all table checks stay satisfied) and proves the
   exact replay is refused without dropping any constraint.
5. **Exact M1.09 result vocabulary.** Replaced the lossy `outcome + selection_mode`
   pair with a single `result_type` column and function parameter accepting exactly
   `ranked_candidates`, `multi_skill`, `no_match`, `avoid`. Mapping is closed and
   lossless.
6. **Full-set invariant + direct-DML surface.** The statement-level lineage validator
   enforces ranked contiguous `1..N` (max 20), multi-skill selected `2..3` with exactly
   one primary at order 1, no lineage for `no_match`/`avoid`, and immutability of
   decision/lineage/correction rows. A successful selecting decision can never survive
   without its complete valid lineage. No weakening of FORCE RLS zero-policy posture.
7. **Privacy canaries.** Kept the dual canary (suspicious column names + wide
   free-text/binary carrier types) and extended it to assert the new `alt_*` reference
   columns are pure `uuid` (no text carrier). No raw prompt / context / body / feedback
   text / ranking input / token / credential / storage key / path / content digest is
   durable.
8. **Checkpoint + ledger.** This checkpoint documents the corrective findings and the
   exact commands/counts/hashes below. One corrective `PASS_LOCAL_PENDING_CODEX_AUDIT`
   row is appended to the ledger; the prior M2.09 row (274) is preserved byte-for-byte.

## Objects created (forward-only empty create; no backfill/conversion)

1. `private.route_decisions` — `rtd_` public identity, account/device binding, account-
   scoped idempotency (`unique(account_id, request_id)`), exact request id + non-content
   fingerprint, exact `result_type`, bounded timing buckets, the five M1.09 authority
   revisions, replay window (>= 24 h), hard decision expiry (<= 30 d), created timestamp.
   Terminal-immutability trigger denies UPDATE/DELETE.
2. `private.route_decision_selections` — immutable selected/ranked lineage with
   mandatory release: exact `(managed_skill_id, version_id, release_id)` per row via a
   composite account-scoped FK, contiguous `row_kind`/`ordinal` (ranked 1..20,
   selected 1..3), closed role (`primary`/`supporting`), a statement-level full-set
   validator, and per-decision binding uniqueness.
3. `private.route_corrections` — `rtc_` public id, decision/account/device binding,
   closed feedback outcome (`correct`/`wrong`/`unnecessary`/`missed`), optional owned
   alternative lineage (pure UUID), one-slot-unique per decision, scoped idempotency,
   expiry, created timestamp; terminal-immutability.
