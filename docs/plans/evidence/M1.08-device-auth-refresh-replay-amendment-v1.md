# M1.08 additive amendment — exact refresh replay V1

Status: **AMENDMENT_CANDIDATE — independent acceptance required**

This is an additive amendment to M1.08. It never edits or reinterprets the
accepted token, exchange, or key-custody contract. It covers only response-loss
recovery for a committed refresh success. Exchange response loss remains the
accepted revoke-and-re-pair path.

## Exact response and time contract

The service samples one pre-commit integer `response_issued_at` and uses it
for the first response and every exact replay. `db_committed_at` is separately
sampled by the transaction and must be within 30 seconds of that value; it is
audit metadata only and never enters the response, AAD, or expiry formulas.
Access expiry, refresh idle expiry, and the remaining family absolute lifetime
are all anchored to the original `response_issued_at`, never replay arrival.

The byte-authoritative result is status `200`, the fixed values of
`Content-Type`, `Cache-Control`, `Referrer-Policy`, and
`X-SkillMap-Response-Issued-At`, plus the compact UTF-8 response body. HTTP/2
framing and header ordering are not authoritative. The logical replay window
is `server_now < response_issued_at + 600`; runtime ciphertext cleanup is due
by `response_issued_at + 900`. Expired replay is retired-generation reuse and
returns the accepted fixed `invalid_grant` result.

## AEAD format

The exact response bytes are sealed with Web Crypto AES-256-GCM using a fresh
12-byte nonce, a 32-byte random key for a five-minute epoch, and a 16-byte tag
appended to ciphertext. Ciphertext plus tag is at most 2 KiB. A unique
`(replay_key_version, nonce)` is required. The stored plaintext digest and
length must match after decryption. The exact AAD is the 14 LF-terminated
lines in the JSON fixture and includes suite, device/family IDs, idempotency
and request digests, generations, `response_issued_at`, `replay_until`,
response version, body digest, and body byte length.

Any key-version, nonce, ciphertext/tag, AAD, length, or body-digest mismatch
fails closed, emits only a redacted security event, and disables the affected
family. No alternate serializer or key is attempted.

## Key custody and truthful exposure

Replay epoch keys are independent random AES keys, never derived from a
retained lookup root. The selected provider/escrow must prove deletion from
runtime, escrow, deleted-version, and backup surfaces by epoch end plus 930
seconds. If any provider retains a deleted key longer, that longer retention
is the truthful exposure bound and blocks acceptance until explicitly risk-
accepted. Restore may use only an unexpired key; a missing key revokes the
affected family and deletes its ciphertext. No token is regenerated.

Lookup and edge-IP key rings remain separate from replay keys. No raw token,
key, plaintext, or provider error may enter Postgres, logs, evidence, browser
state, argv, environment, or a repository file. The signed Keychain boundary
stores only the credential record and pending tuple; access tokens remain
memory-only.

## Crash, concurrency, and idempotency

The helper persists the exact pending tuple before network transmission and
atomically replaces generation N with N+1 only after validating the exact
response. A crash before commit changes nothing; a committed response followed
by response loss replays the exact bytes. Two exact concurrent requests produce
one successor and the same response. A changed digest for the same key is
always `idempotency_conflict`; replay never creates a second successor.

## Acceptance gate

1. Independently decrypt the fixed vector and run all tamper/time-bound tests.
2. Prove the Keychain five-operation boundary and crash semantics in the
   separate M3.01 amendment; no plaintext fallback is acceptable.
3. Select an authorized provider/escrow and obtain key-destruction and restore
   receipts, or amend the exposure bound truthfully.
4. Bind this amendment and its JSON fixture hash to a clean candidate receipt.

No API, migration, database grant, provider configuration, ledger entry,
deployment, or live claim is made by this amendment.
