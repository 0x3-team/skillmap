# M3.01 additive amendment — signed launcher and Keychain credential boundary

Status: **AMENDMENT_CANDIDATE — independent reacceptance required**

This receipt amends the M3.01 evidence additively. The accepted platform matrix,

## Required boundary

The supported cloud-auth entry is a signed `SkillMapLauncher`. It verifies
retained JS/package/native hashes, creates a private non-inheritable broker pipe
for the exact child, and directly spawns the separately signed helper. The
helper verifies its parent audit identity, designated requirement, Team ID,
bundle identifier, architecture, cdhash, entitlements, access group, and
package-relative path before any Keychain read. Direct helper invocation,
wrong parent, altered package/hash, missing broker, locked Keychain, and
headless/user-presence failures return fixed errors before secret access.

Requests and responses use a versioned canonical binary TLV payload framed as
`uint32be length || payload`; frames are no larger than 8 KiB and records no
larger than 4 KiB. Unknown, duplicate, missing, out-of-order, truncated, and
oversized fields fail closed. Secrets never occur in argv, environment,
inherited stdout/stderr, logs, crash reports, or evidence. Stderr contains
fixed error codes only.

## Five credential operations

The credential store is separate from the Secure Enclave proof key and uses
`kSecClassGenericPassword`, Data Protection Keychain,
`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, non-synchronizable records,
the exact provisioned access group, and one record per origin/device binding:

1. `credential_load`
2. `credential_commit_exchange`
3. `credential_mark_refresh_pending`
4. `credential_commit_refresh`
5. `credential_delete`

All mutations are serialized by a symlink-safe owner-only lock. Exchange
ambiguity reloads and accepts only exact binding/token equality. Refresh commit
requires the exact pending tuple and response binding. Crashes before update
leave N+pending; crashes after update leave only N+1. Delete is exact-query and
idempotent. No second refresh-token item, plaintext recovery file, preference,
database value, shell value, or workspace state is permitted.

## Reacceptance gate

An approved Apple-silicon signed/notarized runner must produce machine-readable
receipts for caller identity, code signature and entitlements, all five
operations, exact framing limits, direct/wrong-parent denial, locked/headless

Security.framework mutation, and redaction scans. Until that receipt exists,
the matrix remains `BLOCKED_CANDIDATE`; no local Swift compile or test fixture
is a custody proof.

No production helper/package, API, migration, database grant, provider,
signing, deployment, ledger, or live action is performed by this amendment.
